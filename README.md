# Spayr

Невеликий месенджер українською з Flutter-клієнтом для **iOS, Android, Windows і macOS** та окремим сервером у **SERVER**.

## Швидкий запуск на Windows

1. Запустіть **`SERVER/spayr-server.exe`** подвійним кліком. Або відкрийте `SERVER/start.cmd`, щоб вікно залишилося відкритим у разі помилки.
2. Запустіть **`START_CLIENT.cmd`** у корені проєкту. Він відкриває зібраний Windows-клієнт.
3. У клієнті натисніть **«Зареєструватися»**. Адреса сервера на цьому ж комп’ютері — `http://localhost:8080`.
4. Другий користувач реєструється на **тому самому сервері**. Знайдіть його логін через **«Нова розмова»**.
5. Для голосового дзвінка відкрийте розмову й натисніть кнопку телефона. Для групового створіть групу та натисніть ту саму кнопку.

На іншому ПК чи телефоні в тій самій Wi-Fi-мережі вкажіть `http://IP_ВАШОГО_ПК:8080`, наприклад `http://192.168.1.20:8080`. `localhost` на телефоні означає сам телефон. Android-емулятор звертається до ПК через `http://10.0.2.2:8080`. Може знадобитися дозволити доступ до TCP 8080 у Windows Firewall для приватної мережі. Правила брандмауера програма автоматично не змінює.

Готовий клієнт розташований у `build/windows/x64/runner/Release/`. При перенесенні копіюйте **всю папку**, включно з DLL і `data`, або використовуйте архів `dist/Spayr-Windows.zip`. Сервер переноситься **одним `spayr-server.exe`**: Go, Python, Node.js, Docker, MySQL чи окремий TURN-процес на цільовій машині не потрібні.

## Що працює

- Реєстрація, вхід, вихід і відкликання поточної сесії; пароль хешується bcrypt. Токен зберігається у захищеному сховищі ОС, у серверній БД — лише його SHA-256.
- Пошук користувачів, особисті й групові чати, текст до 4000 символів, історія зі сторінками, непрочитані повідомлення, статус прочитання, присутність та індикатор набору.
- Чернетки під час перемикання чатів у поточному сеансі. Повтор запиту надсилання з тим самим ідентифікатором не створює дубль повідомлення.
- Автоматичне перепідключення та синхронізація історії після обриву мережі.
- **Особисті й групові аудіодзвінки до 8 одночасних учасників**: запрошення, прийняття/відхилення, приєднання до поточного дзвінка, mute, завершення, перемикання гучного зв’язку на телефоні.
- Адаптивний інтерфейс: дві колонки на комп’ютері, окремий список і розмова на телефоні; кнопки дзвінка залишаються доступними при відкритій клавіатурі.
- **SQLite-файл** `SERVER/data/spayr.db`. Сервер сам створює таблиці та налаштування.

## Дзвінки й затримка

Клієнти обмінюються зашифрованим аудіо **WebRTC / Opus**. WebSocket-сервер передає запрошення, SDP та ICE-кандидати; голос не завантажується як HTTP-файли та не записується сервером. У налаштуваннях Opus задано mono та максимальний середній бітрейт 32 кбіт/с; увімкнено підтримувані платформою придушення шуму й акустичного відлуння.

Для невеликих груп використана **mesh-схема**: кожний учасник з’єднується з рештою. Якщо NAT дозволяє, аудіо йде напряму. Якщо прямий маршрут неможливий, використовується **TURN, вбудований у той самий серверний executable**. TURN підтримує UDP і TCP транспорт клієнта та тимчасові облікові дані на 24 години. Безперервні виклики довше доби в цій версії не підтримуються; після завершення строку TURN-даних слід приєднатися знову.

Це зменшує кількість проміжних вузлів, але **фіксовану чи «нульову» затримку гарантувати не можна**. На неї впливають Wi-Fi, мобільна мережа, відстань між людьми та місце розташування TURN. Показник **RTT** у дзвінку — виміряний час проходження туди-назад для найповільнішого активного з’єднання, а не вимір повної затримки голосу від мікрофона до динаміка. За відсутності статистики число не вигадується.

У групі з 8 людьми кожен передає до 7 аудіопотоків: потрібні стабільна мережа й достатня вихідна швидкість. Для великих конференцій потрібна інша архітектура — SFU. Вона в цю версію не входить.

## Сервер через інтернет

Без `public_ip` TURN вимкнений. Локальні та доступні прямі маршрути можуть працювати через STUN, проте **для надійніших дзвінків між різними мережами налаштуйте TURN**.

1. Розмістіть сервер на машині з публічною IPv4 або налаштуйте проброс портів на маршрутизаторі. За CGNAT простого пробросу портів недостатньо — потрібен доступний з інтернету сервер.
2. Зупиніть сервер і відредагуйте автоматично створений `SERVER/server.json`:

```json
{
  "listen": "0.0.0.0:8080",
  "database": "data/spayr.db",
  "public_ip": "203.0.113.10",
  "turn_port": 3478,
  "relay_min": 49160,
  "relay_max": 49260,
  "tls_cert": "cert.pem",
  "tls_key": "key.pem",
  "allow_registration": true
}
```

`203.0.113.10` — лише адреса-приклад. Замініть її реальною публічною IPv4. `cert.pem` і `key.pem` — ваші чинні TLS-сертифікат із ланцюжком довіри та приватний ключ для домену сервера. Сервер сам обслуговує HTTPS/WSS, окремий вебсервер не обов’язковий. Сертифікат потрібно отримати й поновлювати самостійно; перевірка сертифікатів у клієнті не вимикається.

3. Відкрийте/пробросьте **TCP 8080**, **UDP і TCP 3478**, **UDP 49160–49260**. Пробросіть діапазон relay-портів без зміни їхніх номерів. Альтернативні порти задаються в конфігурації. Якщо TCP 3478 заблокований мережевою політикою клієнта, обхід через TURN/TLS 443 у цій версії не реалізований.
4. Запустіть той самий `.exe` та вкажіть у клієнтах `https://ваш-домен:8080`.
5. Після реєстрації потрібних користувачів за бажанням встановіть `allow_registration: false` і перезапустіть сервер.

HTTP передає повідомлення та облікові дані без TLS, тому використовуйте його тільки в довіреній тестовій локальній мережі. Android дозволяє cleartext для локального запуску; Apple-конфігурації дозволяють локальну мережу. Для зовнішніх адрес використовуйте HTTPS. У суворій релізній конфігурації Android можна змінити `usesCleartextTraffic` на `false`.

## Збірка з вихідного коду

Потрібен Flutter **3.44.1 / Dart 3.12.1** або сумісніші нові версії. Залежності зафіксовані в `pubspec.lock`.

```powershell
flutter pub get
flutter analyze
flutter test
flutter build windows --release
flutter build apk --release
```

Android потребує Android SDK / Java 17 та Android 7.0+ (мінімум береться з поточної Flutter SDK). Поточний Android `release` використовує тестовий ключ із Flutter-шаблону; перед публікацією налаштуйте власне підписання й унікальний application ID.

На Mac з Xcode:

```sh
flutter pub get
flutter build macos --release
flutter build ios --release
```

Для встановлення iOS на реальний пристрій налаштуйте Apple Team, Bundle ID і підписання в Xcode. У проєкті додано опис доступу до мікрофона, доступ до локальної мережі, macOS network/audio entitlements та Keychain entitlements. Реальні Apple-збірки необхідно перевірити на Mac.

Адресу сервера можна задати під час збірки:

```sh
flutter build windows --release --dart-define=SPAYR_SERVER=https://chat.example.com
```

Змінена адреса в екрані входу має пріоритет після її збереження.

Для збірки сервера потрібен **Go 1.26+** лише на машині розробника:

```powershell
cd SERVER
.uild.ps1
```

На Linux/macOS: `sh SERVER/build.sh`. Після компіляції достатньо одного `spayr-server` під відповідну ОС. `go run . -config server.example.json` придатний для розробки. Звичайний executable шукає конфігурацію **поруч із собою**, незалежно від поточної папки термінала. Альтернативний шлях: `spayr-server.exe -config C:\Spayr\server.json`.

## Межі цієї версії

- Це робоча початкова версія, **аудіо без відео**. Немає вкладень, редагування/видалення повідомлень, зміни складу вже створеної групи, відновлення пароля чи панелі адміністратора.
- **Вхідні дзвінки працюють у відкритому застосунку.** PushKit/CallKit для iOS, FCM/ConnectionService і foreground service для Android не інтегровані. Доставка виклику в закритий застосунок і продовження дзвінка при блокуванні/призупиненні ОС не гарантуються.
- При втраті WebSocket активний дзвінок завершується локально, звільняючи мікрофон. Після перепідключення треба приєднатися знову. Не робиться неправдивий показ «у дзвінку», коли сигнального зв’язку немає.
- Текстові повідомлення зберігаються на сервері у відкритому вигляді в SQLite; **наскрізного шифрування тексту немає**. Адміністратор сервера має доступ до БД. Для мережі потрібен HTTPS. Голос використовує DTLS-SRTP; TURN пересилає зашифровані медіапакети.
- Для ICE за замовчуванням використовуються публічні STUN Google і Cloudflare. Вони бачать мережеву адресу клієнта, але не зміст повідомлень або голосу. Їх можна замінити в `SERVER/turn.go`.
- Запрошення без відповіді завершується за 45 секунд. Коли в уже з’єднаному дзвінку лишається одна людина, дзвінок закривається для всіх.
- Сервер — один процес і одна SQLite-БД. Горизонтальне масштабування, push-черги та промисловий моніторинг не реалізовані.

## Перевірки

- Сервер: інтеграційні тести REST/WebSocket для входу, відкликання сесії, прав доступу, дублів повідомлень, SQLite, пагінації, непрочитаних, mute, ліміту 8 учасників і виходу з групового дзвінка.
- Вбудований TURN: реальне виділення relay-адреси з авторизацією й перевіркою діапазону портів.
- Групове медіа: три програмні Pion WebRTC-клієнти, SDP через справжній авторизований WebSocket-сервер, ICE/DTLS/SRTP і отримання Opus-пакетів у всіх шести напрямках. Це перевірка медіатранспорту; вона не замінює прослуховування мікрофонів на чотирьох платформах або тест через мобільних операторів.
- Flutter: перевірки URL, синхронізації після обриву, недоставлених повідомлень та статусів прочитання; widget-тести екранів 390/1440 px і групового дзвінка на 360 px з відкритою клавіатурою. Знімки — `test/goldens/`.
- **На цій Windows-машині зібрано Windows-клієнт і сервер. Android/iOS/macOS не зібрані:** немає Android SDK та Mac/Xcode. Затримку на фізичних пристроях не виміряно.

```powershell
flutter analyze
flutter test
cd SERVER
go test -count=1 -v ./...
go vet ./...
```

Для перевірки здоров’я сервера відкрийте `http://localhost:8080/health` (або HTTPS-адресу після налаштування TLS). Endpoint не повертає облікових даних.

## Дані та резервна копія

Поряд із `spayr.db` під час роботи існують SQLite WAL/SHM файли. Для простої узгодженої копії **зупиніть сервер**, скопіюйте всю папку `SERVER/data` і `server.json`, а потім запустіть сервер. Не копіюйте лише `.db` під час активного запису. Налаштування, база, приватні ключі та runtime-бінарники виключені через `.gitignore`.

## Структура

```text
lib/
  api.dart                  HTTP, адреса сервера, WebSocket
  chat_controller.dart      Сесія, чати, синхронізація
  call_service.dart         WebRTC, мікрофон, ICE, статистика
  models.dart               Моделі
  ui/                       Адаптивні екрани
SERVER/
  main.go                   HTTP API та SQLite
  realtime.go               Події й кімнати дзвінків
  turn.go                   Вбудований TURN
  server_test.go            Інтеграційні та медіатести
  spayr-server.exe           Готовий сервер Windows
  build.ps1 / build.sh       Збірка сервера
  start.cmd                 Запуск із збереженням помилки у вікні
  server.example.json       Приклад конфігурації
START_CLIENT.cmd            Запуск готового Windows-клієнта
```

Технічна документація залежностей: [Flutter WebRTC](https://pub.dev/packages/flutter_webrtc), [Pion TURN](https://github.com/pion/turn), [Flutter Secure Storage](https://pub.dev/packages/flutter_secure_storage), [SQLite для Go](https://pkg.go.dev/modernc.org/sqlite). Шрифт [Manrope](https://github.com/google/fonts/tree/main/ofl/manrope) включений із ліцензією SIL OFL у `assets/fonts/OFL.txt`.
